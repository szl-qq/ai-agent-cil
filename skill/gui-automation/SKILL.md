# 图形界面自动化

## 基本循环

```
run_command(启动程序, wait=false)   →  拿到「窗口进程」PID
send_keys(pid=…, text="…")          →  输入内容
send_keys(pid=…, keys="…")          →  按键 / 快捷键
read_file / run_command             →  验证结果
```

`run_command` 返回的**「窗口进程」PID 才是输入目标**；它同时给出的「启动器进程号」是 `cmd.exe` 包装进程，没有窗口，拿它去输入一定失败。

## 按键序列写法

| 写法 | 含义 | 写法 | 含义 |
|---|---|---|---|
| `{ENTER}` | 回车 | `{TAB}` | 切换焦点 |
| `{ESC}` | 取消 | `{BACKSPACE}` | 退格 |
| `{F1}`–`{F12}` | 功能键 | `^s` | Ctrl+S |
| `^a` / `^c` / `^v` | 全选 / 复制 / 粘贴 | `%{F4}` | Alt+F4 |

`text` 与 `keys` 可同时给：**先输入 text，再发 keys**。所以「输入内容后回车」用 `{ text: "内容", keys: "{ENTER}" }` 一次调用即可。

## 在 GUI 里新建 / 编辑文件并保存

1. 启动程序拿到窗口 PID
2. `send_keys(pid, text=正文)` 输入内容
3. `send_keys(pid, keys="^s")` 触发保存
4. **等约 2 秒**让保存对话框弹出
5. `send_keys(pid, text="完整路径", keys="{ENTER}")` 落盘
6. **`read_file` 读回确认**——不验证就等于没完成

两个关键点：

- **路径必须用 Windows 反斜杠格式**（`C:\dir\file.txt`）。正斜杠会被保存对话框当成非法字符，保存静默失败。
- **保存对话框与主窗口同属一个进程**，继续用同一个 `pid` 就行，不用另找窗口。工具会优先把弹出的对话框作为输入目标。

## 关闭程序

**优先 `send_keys(pid, keys="%{F4}")`** —— 走应用自身的关闭流程，不会丢未保存的数据。

确需强制结束时用 `taskkill /PID <进程> /T /F`（已限定到该进程树）。

**禁止 `taskkill /IM <程序名>`** —— 那是按名字全量强杀，会一并杀掉用户自己打开的同类窗口。实测模型曾用它一次杀掉 6 个 Firefox 进程。

## 常见坑

- **复杂界面先聚焦**：向浏览器页面、富文本编辑器这类界面注入按键前，必须先让目标输入框获得焦点（用 `{TAB}` 导航，或先用鼠标/快捷键定位），否则按键会被页面自身的快捷键截获（例如 Firefox 里直接输入会弹出"快速查找"栏）。若只是要取网页文字，直接用 `fetch_url`，不要动用浏览器。
- **抢前台可能失败**：Windows 有前台锁定保护，工具会自动重试若干次。若仍失败，会明确报错并请你先手动点一下那个窗口——此时不要改用其它方式硬来。
- **不要用剪贴板代替输入**：「复制到剪贴板，请你自己粘贴」等于任务没完成。
- **先确认程序真的启动了**：启动信息里的窗口标题能帮你确认打开的是哪个程序。
