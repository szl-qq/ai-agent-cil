# 联网调研

## 一、先判断：到底要不要联网

**默认不联网。** 只有命中下面任意一条才动手：

- 信息本身随时间变化：天气、汇率、股价、比分、油价、航班
- 问题里有「最新 / 当前 / 现在 / 今天 / 最近 / 今年」：版本号、发布日期、人事、政策、赛事
- 需要外部事实核验，而本机文件回答不了
- 需要某个**本机没有的**库、接口、命令行工具的用法

**不要联网的情况**（直接回答或读本机文件）：

- 通用知识、概念解释、语言翻译、数学计算、代码语法
- 关于本机项目或文件的问题 → 先 `read_file` / `search_text` / `find_files`
- 用户提供的材料里已经写了答案

代价参考：一次抓取约 0.3~1.5 秒，并往上下文里塞进几千到上万字符。**不确定时宁可先抓一个最可能命中的地址，也不要连抓五个页面碰运气。**

### 「打开网站」不是「抓取网站」

| 用户说法 | 该做什么 | 用哪个工具 |
|---|---|---|
| 「打开 deepseek.com」「帮我打开这个网址」「打开浏览器访问 X」 | **屏幕上要真的出现浏览器窗口** | `run_command` 执行 `start <url>` |
| 「查一下 X 网站」「帮我看看这个页面写了什么」「获取 X 的内容」 | 你自己把内容读回来告诉用户 | `fetch_url` |

用 `fetch_url` 去应付「打开」，用户屏幕上什么都不会发生，**会被一眼看穿**（"根本没打开"）。反过来，用户只是要一段信息时，也不必真的拉起浏览器——那更慢，还会在他桌面上留个窗口。

判断不准时看动词：**「打开 / 访问 / 帮我进入」→ 启动浏览器；「查 / 看 / 获取 / 总结 / 是什么」→ 抓取内容。** 两者都要时（先打开、再读给用户听）就两步都做。

## 二、优先直取接口，别抓网页

能用 JSON 接口就别去解析 HTML。下列地址在**本机实测可用**（2026-10）：

| 需求 | 直取地址 | 说明 |
|---|---|---|
| 天气（最省） | `https://www.weather.com.cn/data/sk/101010100.html` | 101010100 为北京，纯 JSON，实测 113ms |
| 天气（一行文本） | `https://wttr.in/Beijing?format=3`，配 `user_agent: curl/8.4.0` | **必须用 curl UA**，浏览器 UA 会返回一大坨 HTML |
| 汇率 | `https://open.er-api.com/v6/latest/USD` | JSON，可换 CNY/EUR |
| npm 包最新版 | `https://registry.npmjs.org/<包名>/latest` | 取 `version` 字段 |
| PyPI 包 | `https://pypi.org/pypi/<包名>/json` | 取 `info.version` |
| GitHub 仓库 | `https://api.github.com/repos/<owner>/<repo>` | star、更新时间、默认分支 |
| HuggingFace 模型搜索 | `https://hf-mirror.com/api/models?search=<关键词>&limit=20&sort=downloads&direction=-1` | JSON，含 id / likes / downloads / tags / createdAt，**一条一块，直接读** |
| HuggingFace 单模型 | `https://hf-mirror.com/api/models/<owner>/<模型名>` | 含 `downloads` 与 `downloadsAllTime` |
| HuggingFace 文件清单 | `https://hf-mirror.com/api/models/<owner>/<模型名>/tree/main` | 每个文件名 + 字节大小，下载前先看这个估体积 |
| 公网 IP / 归属地 | `https://ipinfo.io/json` | 含城市、运营商 |
| 加密货币 | `https://api.coingecko.com/api/v3/simple/price?ids=bitcoin&vs_currencies=cny` | 可换币种 |

**实测不可达，别浪费调用**：`zh.wikipedia.org`（维基百科）、`api.ipify.org`、`www.google.com`、`huggingface.co`（主站，改用上面的 hf-mirror 镜像）。

### ⚠️ 有些站点的网页是 JS 渲染的，抓 HTML 拿不到数据

`hf-mirror.com` 就是典型：模型页与搜索页由前端框架渲染，**HTML 里只有导航骨架、没有任何模型数据**。抓页面只会得到一串菜单，看起来"什么都没查到"。这类站点必须走它的 `/api/` 接口。

判断方法：抓回来的内容全是导航链接、看不到任何具体条目或数字，就说明踩到了这种页面——**立刻改用 API，不要反复重试同一个地址**。

## 三、确实要搜索时

| 入口 | 地址 | 备注 |
|---|---|---|
| **Bing RSS** | `https://cn.bing.com/search?q=<关键词>&format=rss` | **首选**：直接给出 title / link / description / pubDate |
| Bing 网页 | `https://cn.bing.com/search?q=<关键词>` | 可用，但前段全是导航链接，搜索结果被挤到后面 |
| 百度（移动版） | `https://m.baidu.com/s?wd=<关键词>` | 可用，仍有少量导航噪声 |
| 微信公众号 | `https://weixin.sogou.com/weixin?type=2&query=<关键词>` | |

**搜索优先用 RSS 形态。** 实测 `format=rss` 返回：

```xml
<item>
  <title>北京天气预报,北京7天天气预报…</title>
  <link>https://www.weather.com.cn/weather/101010100.shtml</link>
  <description>北京天气预报，及时准确发布…</description>
  <pubDate>周四, 01 10月 2026 10:02:00 GMT</pubDate>
</item>
```

一条结果一块，标题、地址、摘要、时间齐全，**没有导航菜单噪声**，可直接挑 `<link>` 继续抓。抓别的站点遇到难啃的页面时，也先试把 `?format=rss` / `/rss` / `/feed` 拼到地址上。

**⚠️ 不要用 `www.baidu.com/s?wd=`**：桌面版对非浏览器请求只返回一段 `location.replace(...)` 跳转脚本，被剥离后是**空壳**（实测确认），这是「明明抓了搜索页却什么都拿不到」的最常见原因。

关键词直接写中文即可，URL 不用手工编码（`fetch_url` 会自动处理）。搜索页很长，**只挑最可能命中的一条再抓详情**，不要一次抓五个结果。

## 四、抓回来怎么读

- HTML 已自动转为文本，**链接以 `<https://...>` 形式保留在正文里**，直接从里面挑条目继续跟进。
- **`max_chars` 用默认值（12000），除非你确实只要开头一小段。** 页面导航常把真正的数据挤到几千字符之后，设小了就永远看不见——实测出现过「数据在第 3745 字符、而调用方只取 1000 字符」，于是反复抓空、来回重试。
- 被截断时提示会告诉你「后面还有 N 字符未显示」，此时应**加大 max_chars 重取同一地址**，不要改小，也不用换地址。
- **同一个地址抓一次就够。** 改 `max_chars` 反复抓同一地址不会有不同内容（工具会直接提示「刚抓过，内容完全相同」）。抓不到想要的东西，说明**地址本身不对**——该换形态（API / RSS）或换站点，而不是重试。
- 若返回内容全是导航菜单，说明该页信息密度太低：改用它的 JSON 接口、RSS，或换一个站。
- 多来源冲突时按：官方 > 垂类数据源 > 聚合站 > 论坛。回答时说明来源。
- **引用的每个具体数字都必须是抓到的原文里有的**；找不到就如实说「未获取到该数据」。

## 五、抓不到时的退路（按顺序，每步只试一次）

1. **换协议**：http ↔ https
2. **换域名**：主站不可达时试 API 子域（如 `api.github.com` 之于 `github.com`）
3. **换形态**：网页 → RSS / JSON 接口 / `?format=json`
4. **走浏览器**：`run_command` 执行 `start <url>` 打开，必要时用 `send_keys` 输入关键字并回车。代价高，是最后手段。
5. **如实说抓不到**：讲清试过哪些地址、失败原因，给出用户可自行打开的链接。**绝不能用记忆里的旧数据冒充实时结果。**

## 六、输出要求

- 每个外部事实都要能指出**来源地址**与**获取时间**。
- 不要把抓到的原文整段倒给用户，提炼要点；原文仅在用户明确要求时给出。
- 金额、股价、汇率、健康、法律类信息必须注明「数据来自 X，仅供参考」。
- 单次任务联网调用建议 ≤ 5 次；超了就说明方向不对，先停下来重新想该抓什么。
