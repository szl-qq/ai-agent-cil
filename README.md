# Agent CLI

本机终端 AI Agent：对接任意 OpenAI 兼容接口（默认本机 FreeLLMAPI 网关），支持流式输出、工具调用、技能（Skill）扩展与分级权限。

零第三方依赖，仅需 Node.js ≥ 18.17（推荐 20+）。

## 快速开始

### 方式一：全局命令（推荐）

双击 `install-cli.cmd`，**新开**一个终端，之后在任意目录都能直接用：

```bash
cli               # 交互模式
cli -p "任务"     # 单次执行
cli --help        # 查看全部参数
cil               # 同上（防止输错的别名）
```

卸载：双击 `uninstall-cli.cmd`（只移除 PATH 项，项目文件不动）。

它只把本项目的 `shim/` 目录加到**用户级** PATH——不需要管理员权限，不碰系统 PATH，不影响其它软件。安装脚本用 .NET 的 `SetEnvironmentVariable` 写入，而不是 `setx`：后者会截断超过 1024 字符的值，且用 `setx PATH "%PATH%"` 时会把系统 PATH 悄悄并进用户 PATH——这两种都是常见的 PATH 损坏原因。

### 方式二：不走 PATH

```bash
node bin/agent.mjs              # 交互模式
node bin/agent.mjs -p "列出当前目录并总结项目结构"
```

Windows 也可以直接双击项目根的 `agent-cli.bat`。

已装 npm 的话，还有第三种：`npm link`（由 npm 把 `bin` 字段里的 `cli` / `cil` / `agent` 链到全局目录，不需要手改 PATH）。

首次使用需配置接口地址与密钥，任选其一：

1. 环境变量：`AGENT_BASE_URL` / `AGENT_API_KEY`
2. 密钥文件：程序根目录或工作区根目录的 `agent.key`
3. 命令行：`--base-url` / `--api-key`
4. 配置文件：`./.agent-cli/config.json`（项目级）或 `~/.agent-cli/config.json`（全局级）

**关于工作区**：Agent 的工作区就是**启动时的当前目录**。用全局 `cli` 时，先 `cd` 到目标项目再执行，文件读写与命令执行都以该目录为基准；会话记录与审计日志也会写在该目录的 `.agent-cli/` 下。

```bash
cd D:\some-project
cli                       # 工作区 = D:\some-project
```

## 特性

| 能力 | 说明 |
|---|---|
| 流式输出 | SSE 逐字渲染，含工具调用增量的按序拼接 |
| Markdown 渲染 | 模型输出的 `**粗体**`、`# 标题`、`- 列表`、`>` 引用、`` `代码` ``、链接等转成终端样式，不再把标记符号裸露给用户。跨 chunk 的半截标记会按捺到成对再输出，不会漏出星号；标记已闭合的内容立即输出，保留逐字流式手感；非 TTY / `--no-color` / `--no-markdown` 时整行原样透传，重定向到日志仍可 grep |
| 模型候选链 | `--model a,b,c`，前一个失败自动降级，瞬时故障指数退避重试 |
| 工具集 | 读/写/精确编辑文件、目录浏览、通配查找、内容检索、命令执行、网页抓取（自动编码中文 URL、保留链接、剥离导航噪声）、GUI 键盘输入、计划维护、技能加载 |
| 抓取去重 | 同一地址 30 秒内重复抓取直接复用缓存并提示「内容完全相同」，避免反复抓同一页空耗；截断时明确告知「后面还有 N 字符」，引导加大 `max_chars` 而不是重复重试 |
| 并行调度 | 同一轮内的**连续只读**调用（读取、检索、抓取）并行执行；写操作保持串行，结果仍按原顺序回写 |
| 资源保护 | 单文件读取上限 8 MB、网页响应上限 5 MB、工具输出按配置截断、审计日志超限自动轮转 |
| 不阻塞会话 | GUI 程序（记事本、浏览器、编辑器）自动切换为后台启动，并回报**真正的窗口进程 PID**；常驻服务用 `wait=false`；命令超时被终止时给出改用后台的提示；给出的关闭建议是「先用 `%{F4}` 优雅退出」，而不是按程序名全量强杀 |
| GUI 自动化 | `send_keys` 向已打开的窗口注入键盘输入，可驱动记事本等程序完成"输入内容 → `Ctrl+S` → 保存对话框填路径 → 落盘"的完整闭环；同样适用于 `start <url>` 拉起的浏览器 |
| 输出编码自适应 | Windows 内置命令按 GBK 输出、现代工具按 UTF-8 输出，自动判别解码；`taskkill`/`dir` 等的中文提示不再显示为乱码 |
| 中断彻底 | Ctrl+C 既中断模型请求，也终止正在运行的子进程 |
| 技能系统 | `skill/<名称>/SKILL.md` 自动发现，元数据注入系统提示，模型按需加载全文指令 |
| 分级权限 | 默认放行；删除/覆盖/关机类命令及密钥、凭据、浏览器数据等隐私访问才请求授权；支持三态确认与会话级授权 |
| 上下文经济 | 系统提示与工具说明只写最小必要信息；技能在提示里**只列名字**，用途按需用 `list_skills` 查询；主循环**每轮**都检查用量并自动压缩；重复抓取同一地址走缓存 |
| 上下文管理 | 接近阈值自动摘要压缩，保留最近若干轮与文件路径等关键事实；超长历史按"保头保尾"裁剪；压缩时按消息边界切分，不会切出孤儿 `tool` 消息 |
| 会话持久化 | 自动保存至 `.agent-cli/sessions/`，支持 `--resume [名称]` / `--list-sessions` 恢复 |
| 审计日志 | 授权决策写入 `.agent-cli/audit.log`（JSONL） |
| 中断控制 | Ctrl+C 中断当前任务而非退出进程 |

## 技能（Skill）

在项目根目录新建 `skill/`，每个技能一个子目录，内含 `SKILL.md`：

```
skill/
  my-skill/
    SKILL.md          # 必需：含 frontmatter 的指令文档
    script.py         # 可选：附带脚本，技能指令中可调用
```

`SKILL.md` 格式：

```markdown
---
name: my-skill
description: 一句话说明何时使用本技能（模型据此决定是否加载）
---

# 正文指令
分步骤写清执行流程、命令、输出格式与注意事项。
```

加载优先级：`<工作区>/skill` > `<工作区>/skills` > `<程序目录>/skill` > `~/.agent-cli/skills`。
同名技能以高优先级目录为准。修改技能后在会话内输入 `/reload` 即可生效。

内置示例：`system-report`（系统体检）、`project-scan`（项目结构扫描）、`web-research`（联网调研）、`gui-automation`（图形界面操作）。

`web-research` 收录了**本机实测可用**的直取接口与搜索入口（Bing RSS 优先、百度须用 `m.` 域名），以及"哪些地址在本机不可达"和"抓不到时的退路"，避免模型在墙外站点上空耗调用。它同样强调**默认不联网**——通用知识、本机代码问题、用户已给的材料都不该触发抓取。

`gui-automation` 收录启动程序、注入按键、处理保存对话框、关闭窗口的完整流程与踩坑。

**技能是按需加载的**：系统提示里只列出技能名（不占多少上下文），用途说明通过 `list_skills` 查询，完整指令通过 `use_skill` 载入。技能描述动辄上百字符，若每轮都随系统提示发送，会在整个会话中反复计费，而绝大多数轮次根本用不到技能。

## 权限模型

| 场景 | 行为 |
|---|---|
| 普通读写、只读检索、普通命令 | 自动放行 |
| 删除/格式化/关机/强杀/破坏性 git 等命令 | 请求授权 |
| 读取或写入密钥、凭据、浏览器数据、系统凭据库 | 请求授权 |
| 覆盖已存在文件 | 请求授权 |
| 向 GUI 窗口注入键盘输入（`send_keys`） | 请求授权——它等于一条绕过命令授权的通道 |

授权提示支持三态：`y` 本次允许、`a` 本会话内放行同一工具、`N` 拒绝。
另有三种模式：`smart`（默认）、`strict`（所有写操作都确认）、`yolo`（全部放行）。

配置化规则优先级最高：

```json
{ "permission": { "allow": ["run_command:git status*"], "deny": ["run_command:*format *"] } }
```

  src/tools.mjs          工具定义与实现
  src/permissions.mjs    风险分类与授权决策
  src/skills.mjs         技能发现与加载

## 已知限制

- 上下文用量为字符估算（约 2.6 字符/token），非精确 tokenizer 计数。
- 流式模式下部分网关不返回 `usage`，此时用量统计以估算值为准。
- 未提供沙箱隔离，工具直接以当前用户权限运行，敏感场景请使用 `--strict` 并审阅每次授权。
- 若宿主环境存在程序黑名单（如企业安全策略禁用 `wmic`），被拦截的命令会如实报错，属预期行为。
- GUI 自动化依赖目标窗口取得前台焦点。Windows 有"前台锁定"保护，抢占会被间歇性拒绝，程序会自动重试；若持续失败会明确报错并要求先手动点击该窗口一次，而不是把按键打进无关窗口。
- `send_keys` 仅在 Windows 上注册（依赖 Win32 `SendInput`）。
- 全局 `cli` 命令依赖 PATH 里的绝对路径。**移动或重命名项目目录后需要重新运行 `install-cli.cmd`**；在那之前 `cli` 会失效（旧的 PATH 项指向已不存在的路径）。`uninstall-cli.cmd` 可以清掉遗留项。
